KB, MCP ou instrução?

Onde deve morar cada informação de que um agente precisa.

Tempo: ~15 min Pré-requisito: nenhum Plano: voltar ao plano de estudo
O ganho desta lição

Ao final, você classifica qualquer informação de um agente em um de três lugares e justifica a escolha. É a primeira pergunta que cada área vai te trazer quando quiser "colocar o conhecimento dela no agente".

Por que isso é o centro da sua função

A Anthropic resume um agente como um modelo de linguagem usando ferramentas em loop, e trata o contexto (o que o modelo "vê" a cada passo) como um recurso finito, que precisa ser gasto com cuidado.Fonte: Effective context engineering for AI agents, Anthropic Engineering. Tudo o que o agente sabe chega a ele por um de três caminhos. Escolher o caminho errado gera os problemas clássicos: respostas desatualizadas, vazamento de dado de uma pessoa para outra, ou um agente lento e caro com contexto inchado.

Os três lugares

InstruçãoRegras de comportamento que valem para toda conversa: tom, escopo, o que não fazer, quando encaminhar. Sempre presentes no contexto, então precisam ser curtas.
Base de conhecimento (KB)Documentos estáveis (políticas, manuais, FAQs). O agente busca os trechos relevantes antes de responder: é o RAG.
Ferramenta via MCPDados que mudam a toda hora ou por pessoa, e ações em sistemas. O agente chama uma função e recebe a resposta na hora.

KB No Copilot Studio isso é uma fonte de conhecimento: SharePoint, Dataverse, arquivos enviados ou conectores.Knowledge sources overview, Microsoft Learn. Na AWS, o equivalente é o Amazon Bedrock Knowledge Bases. O conteúdo é indexado e quebrado em pedaços (chunks), e a busca traz só os pedaços relevantes para a pergunta.

MCP O Model Context Protocol é um padrão aberto para um agente descobrir e chamar ferramentas de um servidor. O Copilot Studio adiciona um servidor MCP como ferramenta do agente: ele lê a lista de ferramentas que o servidor expõe e passa a chamá-las.Add an MCP server to your agent as a tool, Microsoft Learn. Na AWS, o AgentCore Gateway expõe APIs e funções como ferramentas MCP. A resposta é calculada na hora da chamada. Quando a conexão usa a identidade do usuário (o Copilot Studio pede que ele se conecte ao servidor), o dado devolvido é o daquela pessoa, naquele momento. Como configurar essa autenticação é assunto da Fase 5.

Instrução É o texto fixo que define o papel do agente. Como entra em todo turno, cada linha custa contexto: regras sim, conteúdo de manual não.

O teste das três perguntas

Uma regra prática (minha, não da documentação) para decidir, na ordem:

  1. É regra de comportamento que vale para toda conversa? Então é Instrução.
  2. A resposta muda com o tempo ou com a pessoa, ou exige fazer algo num sistema? Então é MCP.
  3. Está escrita num documento e muda pouco? Então é KB.
Nuance: a fronteira técnica é borrada

Os Copilot connectors do Microsoft 365 têm dois modos: synced, que indexa o conteúdo no Microsoft Graph (comportamento de KB), e federated, que busca em tempo real via MCP sem indexar.Extend Copilot's knowledge with Copilot connectors, Microsoft Learn. A AWS permite expor uma Knowledge Base como alvo do AgentCore Gateway, ou seja, como ferramenta MCP.Connect a knowledge base to a gateway, Amazon Bedrock. Por isso, decida primeiro pela natureza da informação (estável ou viva, geral ou por pessoa, saber ou fazer) e só depois escolha a tecnologia.

Recupere antes de praticar

Escrever de memória cansa mais que reler, e é justamente isso que faz o conteúdo ficar. Não pule.

Pratique: classifique

Para cada informação de um agente interno hipotético, escolha onde ela deve morar. O feedback é imediato.

Leve para o mundo real

Pense em três informações que um agente da sua futura área precisaria (por exemplo: o regulamento de um processo, o status de um projeto, uma regra de priorização). Classifique cada uma com o teste das três perguntas e traga a classificação para o chat. Eu dou o feedback e, se ficar claro que você domina, registro isso no seu histórico de aprendizado.
